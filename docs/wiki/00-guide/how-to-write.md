# 위키 작성 가이드

## 원칙
- 최종 스펙은 SPEC.md, 위키는 **결정의 배경·검토한 대안·이유**를 적는다. 스펙을 복사하지 않는다.
- PR이 요구사항이나 중요 설계를 추가·변경하면 같은 PR에서 `docs/wiki/`를 함께 수정한다.
- 간결하게, 한 문서는 한 주제. 인접 주제는 상대 링크로 연결한다.

## 구조
`docs/wiki/<NN-섹션>/<문서>.md` (섹션은 한 단계만). 최상위 `Home.md`는 목차.
머지 후 `wiki-sync` 워크플로가 평면 위키로 변환한다 (`03-pipeline/briefing.md` → `03-pipeline-briefing`).
사이드바는 자동 생성되고 제목은 각 문서의 첫 `# ` 줄이다.

| 섹션 | 내용 |
|------|------|
| 01-overview | 목표·범위·사용자 |
| 02-sources | 수집 소스 |
| 03-pipeline | 정규화·선별·요약 |
| 04-delivery | 게시·메일·푸시 |
| 05-operations | 스케줄·보안·비용·개발 규칙 |
| 06-decisions | 마일스톤·미정 사항·변경 이력 |

## 문서 템플릿
```markdown
# 제목
## 결정            <- 최종안 한두 줄
## 배경·이유       <- 왜 이렇게 정했나
## 검토한 대안     <- 버린 안과 버린 이유 (있을 때)
## 변경 이력       <- `YYYY-MM-DD PR #n: 무엇이, 왜 바뀌었나`
관련: [다른 문서](../섹션/문서.md)
```

## 링크 규칙
- 다른 위키 문서는 상대 경로 `.md` 링크로 쓴다 (저장소와 위키 양쪽에서 동작).
- 링크 텍스트는 문서 제목과 맞춘다. 저장소 파일은 `https://github.com/degru82/ai-news-bot/blob/main/...` 전체 URL.

## 주의
- 배경·이유가 대화·리뷰에서 확인되지 않은 것은 "추정"으로 표시하고, 확인되면 고친다.
- 비밀값·구독자 주소·회사 내부 정보는 쓰지 않는다 (위키도 공개될 수 있음).
