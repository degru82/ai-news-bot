# 운영·보안·개발 규칙

## 결정
- 스케줄: cron `0 21 * * *`(KST 06:00) + `workflow_dispatch`(`date`, `dry_run`). 실행 10분 이내 목표.
- 전체 실패: 푸시로 실패 알림+로그 링크, 메일 미발송. 소스 일부 실패는 부분 발행.
- 월 API 비용 $10 이하, 실행마다 추정 비용 로그.
- 위키: `docs/wiki/`가 원본, main 머지 시 GitHub Wiki로 자동 동기화 ([작성 가이드](../00-guide/how-to-write.md)).

## 배경·이유
- 06:00 실행은 07:00 발행 전 여유 확보. `date` 입력은 특정 날짜 backfill용.
- 어설픈 메일을 보내는 것보다 전체 실패는 조용히 운영자에게만 알리는 편이 안전.
- 수집 텍스트는 신뢰할 수 없는 입력: 태그 격리, 스키마 검증, HTML 이스케이프.
- 비밀값·구독자 주소는 코드·로그·fixture·`site/`에 두지 않는다.
- 개발 규칙(CLAUDE.md): PR당 마일스톤 하나(리뷰 범위 축소), 외부 호출은 인터페이스 뒤+가짜 구현(네트워크·비밀값 없이 CI 통과), 프롬프트는 `prompts/`·설정은 `sources.yaml`.
- 위키 동기화: 사람이 읽는 설계 근거를 코드와 함께 PR 리뷰받기 위해 저장소를 원본으로 두고 위키는 읽기용 사본으로 취급. 위키 직접 수정은 다음 동기화에 덮어써진다.
